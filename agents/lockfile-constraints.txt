# Platform-split version constraints fed to `uv pip compile --constraint` by
# scripts/gen-lockfile.sh (LLD 0055 B1a). This is the ONLY hand-maintained input
# to the otherwise-universal lockfile; the lockfile itself stays generated.
#
# cryptography: 49.x dropped the macOS x86_64 (Intel) wheel — it ships
# macosx_11_0_arm64 only — so the darwin/amd64 release leg (macos-15-intel) cannot
# `pip install --only-binary :all:` it. Cap Darwin to 48.0.1, the newest release
# that still ships a macosx_10_9_universal2 wheel (covers Intel AND Apple Silicon).
# Non-Darwin is left UNpinned here so uv emits the complement marker automatically
# and `make freeze-deps --upgrade` can still bump linux. 48.0.1 is NOT CVE-clean:
# its advisories are waived, each with an expiry, in .pip-audit-ignore (the
# preflight's pip-audit gate) and .trivyignore (the release CVE gate). Renew them
# only after re-tracing, per docs/guides/release_process.md "Vulnerabilities".
#
# REMOVE this constraint (and re-lock) when EITHER:
#   (a) cryptography ships a macOS x86_64 wheel again, OR
#   (b) the darwin/amd64 leg is dropped from .github/workflows/release.yml
#       (Intel-mac runner EOL ~Fall 2027 — see the build-binary matrix comment).
# Darwin is CAPPED, not pinned to latest: 49.0.0 and 50.0.0 ship NO Intel
# macOS wheel (verified on PyPI — 48.0.1 has 3 universal2 wheels, 49.0.0 and
# 50.0.0 have none), and release.yml:72 still builds darwin/amd64 on
# macos-15-intel. Dependabot #122 moved this pin 48.0.1 -> 50.0.0 and left
# the rationale comment untouched, which silently re-broke that leg.
cryptography==50.0.0; sys_platform == "darwin"
# The complement is stated EXPLICITLY so the marker fork is deterministic.
# Left implicit, uv unifies both platforms onto one version whenever a single
# version satisfies everything, and the split the darwin/amd64 leg depends on
# silently disappears — which is what the freshness gate caught.
cryptography>=50.0.0; sys_platform != "darwin"

# Security floors for transitive deps flagged by the audit-python gate
# (scripts + .github/workflows audit `agents/requirements-frozen.txt` with
# pip-audit). Both are pure-Python (universal wheel), so no marker split is
# needed — one version for every platform. Raise/remove each floor once the
# requirers (urllib3 via requests; pyjwt is the sole `cryptography` consumer)
# carry an equal-or-higher minimum on their own and uv resolves above the floor.
#
# urllib3: 2.7.0 is affected by PYSEC-2026-4175/4176/4177 — fixed in 2.8.0.
urllib3>=2.8.0
# pyjwt: 2.13.0 is affected by PYSEC-2026-4140..4152 — fixed in 2.14.0, except
# PYSEC-2026-4141 which needs 2.15.0; floor at 2.15.0 to clear the whole set.
pyjwt>=2.15.0
# filelock: every 3.x is affected by 13 advisories (GHSA-v4x8-3wr5-3wq8 and others),
# fixed only in 4.2.1, with no 3.x backport. litellm 1.104.0 through 1.108.0 cap
# filelock<4.0, so this floor holds litellm at the newest release without that cap
# (1.103.x). litellm 1.109.0rc1 allows filelock<5: a re-lock moves litellm up once a
# stable release does, with no edit here.
filelock>=4.2.1
